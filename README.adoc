= page-context
:description: Asciidoctor/Antora extension that formats page orientation, authorship, classification, and related metadata from page-* attributes — including keyword links to filtered article listings.
:page-audience: Antora / AsciiDoc authors who want page metadata rendered without hand-written lead/footer markup
:page-usage-context: Register under `asciidoc.extensions` in an Antora playbook (or Asciidoctor.js `extension_registry`); optional Antora helper for keyword index pages
:page-doc-type: reference
:page-status: published

Renders **Dublin Core–style**, Quarto/SSG, AsciiDoc revision, and Diátaxis-oriented metadata from `page-*` attributes into a slim teaching byline + lead table (orientation), a footer aside (authorship / classification / colophon), and HTML `<meta>` tags.

Schema version:: `0.6.6`

== Install

[source,bash]
----
pnpm add -D github:antora-supplemental/page-context#v0.6.6
# after npm publish: pnpm add -D @antora-supplemental/page-context
----

== Playbook

[source,yaml]
----
antora:
  extensions:
    # Optional: generate /{component}/keywords/{slug}/ listing pages
    - require: '@antora-supplemental/page-context/antora'
      component: home
      path: keywords
asciidoc:
  extensions:
    - '@antora-supplemental/page-context'
  attributes:
    page-context-active: ''
    page-context-keyword-base: '/home/keywords'
----

== Minimal house schema (Dev-Centr)

[source,asciidoc]
----
= Page title
:description: Short SEO blurb (Antora; not owned by this extension).
:page-audience: New Dev-Centr members adopting agent-rules
:page-usage-context: Full teaching page on the docs hub
:page-orig-author: Ryan Johnson
:page-last-author: Cursor agent on behalf of Ryan Johnson
:page-last-edited: 2026-09-10
----

Agent-assisted credit (source attr):: `{product} on behalf of {human}`
+
Displayed as:: `{human} [avatar] via {product}` — e.g. `Ryan Johnson` + circular pic + `via Cursor` (no parentheses; agent name is not linked)

Do **not** also paste hand-written `Audience role::` / author labeled lists when this extension is active.

== Layout (0.6.6)

[cols="1,3"]
|===
| Zone | Contents

| **Lead outer** (`.page-context-lead`)
| Seamless document chrome (no border/background). Holds the byline and the inner panel.

| **Byline** (`.page-context-byline`)
| `Last updated {date} by {linked name} {circular avatar} via {agent}` — child of the lead aside, **sibling** of the panel (not inside the table). Avatar is after the name; agent product is plain text. Flex `gap` on `.page-context-author` separates name, avatar, and `via` (same cluster in footer author cells).

| **Lead panel** (`.page-context-panel`)
| Subtle border + wash + padding wrapping **only** the key/value table (Audience role, Usage, Status, Source, …).

| **Footer** (`.page-context-footer`)
| Single panel aside: authorship, classification (Document type, Diátaxis, **Keywords**, Tags, …), dates not shown in the byline, rights / identifiers / locale. Author cells use the same name → avatar → `via` chrome.

| **Component home**
| No byline / no Audience role / Usage chrome; authorship + dates in the footer only. Still emits an **empty lead shell** (header zone) so page-edit can attach Source.
|===

`@antora-supplemental/page-edit` may add a **Source** row (`View | Edit`) to the lead table. The VCS provider mark sits on the **Source** key; the value cell is text-only links.

== Keyword links

Footer **Keywords** / **Tags** values are split on commas and rendered as links:

* Class: `page-context-keyword` (muted: `color: inherit`; underline only — not accent/link-blue)
* URL: `{page-context-keyword-base}/{slug}/` (default base `/home/keywords`)
* Slug: lowercased, non-alnum → `-` (e.g. `Search Engine Optimization` → `search-engine-optimization`)

Register `@antora-supplemental/page-context/antora` so those URLs resolve to generated listing pages: articles that use the keyword, grouped by component (a filtered tree). An index is published at `{base}/` (e.g. `/home/keywords/`).

Set `page-context-keyword-base` to match the host component + path (no trailing slash).

== HTML meta

When present, values are also emitted as `<meta>` tags (`author`, `keywords`, `dcterms.*`, `og:*`, `article:*`, `citation_*`, `robots`). Antora’s own `:description:` continues to feed the usual description meta via Antora — use `page-abstract` when you want this extension to emit description as well. Agent credits are plain-human in meta (`Ryan Johnson`, not the via form).

== Behavior

* Teaching byline + lead aside when orientation fields or a byline date exist (component homes still get an empty lead shell).
* Footer aside for authorship / classification / colophon (and on component homes for authorship).
* Markup: `<aside class="page-context …">` with optional byline + `<table class="page-context-table">`.
* Idempotent if a block with role `page-context-lead` / `page-context-footer` already exists.
* Injects baseline CSS + meta via DocInfo `head` (themes may refine with `.page-context` tokens).
* **Does not** format Asciidoctor/Antora `:toc:` / in-doc TOC — that stays a separate block; style it in the UI theme (e.g. Valentus).

=== Component home surface

Org **component start pages** (and hub portal homes) must not show Audience role / Usage context chrome — even when those `page-*` attrs are set (agents / HTML meta still use them). Authorship and dates render in the **footer** only. An empty **lead shell** (panel + table) remains so `@antora-supplemental/page-edit` can place View|Edit in the header zone.

Detect when either:

* `:page-context-surface: component-home` (alias `home`) is set, or
* Antora attrs say this is the default start page: `page-module=ROOT` and `page-relative-src-path=index.adoc`

Section landings (`tutorials/index.adoc`, etc.) keep normal lead chrome.

== Styling (prefer here, not per-hub)

**Soft default:** treat this package as the **point of interpretation** for `page-*` presentation.
Refine shared look in the extension’s baseline CSS (and theme tokens that target `.page-context`), not by forking the same chrome with one-off per-hub supplemental CSS.
Hubs may still set brand tokens; avoid duplicating table/aside layout rules in every docs playbook.

Keys use `text-align: left` (UA `th` defaults to center). Keyword links inherit muted text color with underline only. Footer aside has extra top/bottom margin so end-zone metadata is not stuck to the last body block.
