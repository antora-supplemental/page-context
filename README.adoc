= page-context
:description: Asciidoctor/Antora extension that formats page orientation, classification, authorship, rights, and related metadata from page-* attributes.
:page-audience: Antora / AsciiDoc authors who want page metadata rendered without hand-written lead/footer markup
:page-usage-context: Register under `asciidoc.extensions` in an Antora playbook (or Asciidoctor.js `extension_registry`)
:page-doc-type: reference
:page-status: published
:page-keywords: antora, asciidoctor, metadata, dublin-core, front-matter

Renders **Dublin Core–style**, Quarto/SSG, AsciiDoc revision, and Diátaxis-oriented metadata from `page-*` attributes into a lead aside (orientation + provenance), an optional footer aside (colophon), and HTML `<meta>` tags.

== Install

[source,bash]
----
pnpm add -D github:antora-supplemental/page-context#main
# after npm publish: pnpm add -D @antora-supplemental/page-context
----

== Playbook

[source,yaml]
----
asciidoc:
  extensions:
    - '@antora-supplemental/page-context'
----

Inspired by Dublin Core, Quarto/Pandoc front matter, AsciiDoc `author`/`revdate`/`revnumber`, Open Graph / citation_* meta, and common SSG keys (Hugo/Jekyll/MkDocs).

== HTML meta

When present, values are also emitted as `<meta>` tags (`author`, `keywords`, `dcterms.*`, `og:*`, `article:*`, `citation_*`, `robots`). Antora’s own `:description:` continues to feed the usual description meta via Antora — use `page-abstract` when you want this extension to emit description as well.

== Behavior

* Lead aside prepended when any lead field is set (orientation + provenance **before** body / in-doc TOC).
* Footer aside appended only when colophon fields are set (license, DOI, …).
* Markup: `<aside class="page-context …"><table class="page-context-table">…</table></aside>` — aside is the panel; compact key/value rows inside (keys left-aligned).
* Idempotent if a block with role `page-context-lead` / `page-context-footer` already exists.
* Injects baseline CSS + meta via DocInfo `head` (themes may refine with `.page-context` tokens).
* **Does not** format Asciidoctor/Antora `:toc:` / in-doc TOC — that stays a separate block; style it in the UI theme (e.g. Valentus).

== Styling (prefer here, not per-hub)

**Soft default:** treat this package as the **point of interpretation** for `page-*` presentation.
Refine shared look in the extension’s baseline CSS (and theme tokens that target `.page-context`), not by forking the same chrome with one-off per-hub supplemental CSS.
Hubs may still set brand tokens; avoid duplicating table/aside layout rules in every docs playbook.

Keys use `text-align: left` (UA `th` defaults to center). Footer aside has extra top/bottom margin so end-zone metadata is not stuck to the last body block.
